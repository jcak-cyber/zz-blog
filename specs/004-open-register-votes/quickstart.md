# Quickstart: 开放注册与文章表态（004）

**Feature**: `004-open-register-votes` | **Date**: 2026-08-14  
**目的**: 手工验证注册→登录→本人发文→公开作者名→赞踩互斥；对照 [contracts/api.md](./contracts/api.md) 与 [data-model.md](./data-model.md)。

---

## 前置

1. PostgreSQL 已启动（如 Docker Compose）。  
2. 后端已迁移并 seed（种子用户具备 `username`，能登录）。  
3. `pnpm run dev:back`、`pnpm run dev:front`（或等价脚本）。  
4. 浏览器使用干净配置文件或无旧 Cookie 窗口。

---

## 场景 A — 注册后须再登录

1. 打开 `/register`。  
2. 用户名：`demo_user_1`，密码：`password1`（≥8），提交。  
3. **期望**：成功提示；跳转 `/login`；**未**直接进入作者区；DevTools 无 access/refresh Cookie（或与登录后明显不同）。  
4. 密码改成 `short` 再试新用户名 → **期望**拒绝并提示长度。  
5. 重复占用 `demo_user_1` → **期望**占用提示。  
6. 在登录页用 `demo_user_1` / `password1` 登录 → **期望**进入作者入口。

---

## 场景 B — 本人写作与越权

1. 用户 A（`demo_user_1`）登录，撰写并**立即发布**一篇，记下 slug。  
2. 未登录打开首页与 `/posts/{slug}` → **期望**可见，且显示作者 `demo_user_1`。  
3. 注册并登录用户 B（`demo_user_2`）。  
4. B 打开「我的文章」→ **期望**看不到 A 的稿。  
5. B 直接请求 A 的编辑 URL 或 `GET/PATCH /api/v1/author/posts/{A的id}` → **期望** 404/失败，正文未被改。  
6. A 与 B 使用相同 slug 发布 → **期望**后提交方 409，公开不串文。

---

## 场景 C — 点赞 / 点踩

1. 未登录打开已发布详情，正文下方见赞/踩与计数（可为 0）。  
2. 点击赞 → **期望**引导登录/注册，计数不增加。  
3. 登录 A，点赞 → 计数 +1，按钮为已赞；刷新仍保持。  
4. 再点赞 → 取消，计数 -1。  
5. 点赞后再点踩 → 赞减踩加，状态为已踩。  
6. 用户 B 登录后点赞同一文 → 赞计数再 +1；A 的状态不变。  
7. 网络断开时点踩 → 有失败提示，无「假成功」计数。

---

## 场景 D — 阅读不被打断

1. 未登录刷首页与至少 3 篇详情全文。  
2. **期望**：无强制跳转登录；注册/登录入口不挡正文。  
3. 登录页可见通往注册的链接。
