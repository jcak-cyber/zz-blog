# Feature Specification: 开放注册与文章表态

**Feature Branch**: `004-open-register-votes`

**Created**: 2026-08-14

**Status**: Draft

**Input**: User description: "1、开放账号注册功能，所有人都能注册登录，登录后并且也可以进行文章编辑与发布。2、在图2框选位置新增文章点赞、点踩功能"

**UI 参照**：文章详情页正文下方、页脚上方（图示红框位置）放置点赞 / 点踩控件；控件视觉参照深色底上并排的圆角按钮（拇指向上/下 + 计数），并融入 zz-blog 既有墨色手稿气质（不得照搬无关产品的高饱和社交风）。

## Clarifications

### Session 2026-08-14

- Q: 开放多人写作后，不同用户的文章网址短标识（slug）是否必须全站唯一？ → A: 全站唯一：任意两篇文章不能共用同一 slug
- Q: 注册时用来登录的「账号」应采用哪种标识？ → A: 仅用户名（字母数字等，全站唯一）
- Q: 注册成功后，用户应直接进入已登录状态，还是先去登录页再登？ → A: 注册成功后回到登录页，需再输一次账号密码
- Q: 注册密码的最短长度要求是多少？ → A: 至少 8 位
- Q: 公开文章列表和详情页要不要显示作者用户名？ → A: 列表与详情都显示作者用户名

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 访客自助注册并登录 (Priority: P1)

作为访客，我可以在站点完成账号注册，再用该账号登录，从而获得与既有登录用户相同的写作与发布入口。

**Why this priority**: 开放注册是本功能的核心前提；没有可用的注册→登录路径，后续「人人可写」无法成立。

**Independent Test**: 使用全新用户名仅完成注册并登录，确认进入作者入口且无需站点维护者预置账号。

**Acceptance Scenarios**:

1. **Given** 访客未登录，**When** 打开注册页，**Then** 看到简体中文的注册表单（至少包含用户名、密码与提交；可选显示名），并可提交注册。
2. **Given** 注册信息合法且用户名未被占用，**When** 提交注册，**Then** 注册成功，用户仍为未登录态，并被引导至登录页（可预填用户名），提示可用刚注册的账号登录。
3. **Given** 用户名已被注册或密码不符合基本要求，**When** 提交注册，**Then** 看到明确失败提示，且不会误登录。
4. **Given** 用户刚注册成功并已到登录页，**When** 输入正确用户名与密码提交登录，**Then** 登录成功并可到达作者入口。

---

### User Story 2 - 任意登录用户撰写并发布自己的文章 (Priority: P1)

作为已注册并登录的用户，我可以使用现有撰写台创建、编辑、发布（及既有草稿/撤回等能力范围内）属于我自己的文章；公开读者仍可免登录阅读已发布内容。

**Why this priority**: 「登录后可编辑发布」是用户明确要求的第二半能力；与开放注册共同构成最小闭环。

**Independent Test**: 用新注册账号登录，撰写并立即发布一篇文章，在未登录浏览器打开公开列表/详情验证可见；另一账号不得编辑该文。

**Acceptance Scenarios**:

1. **Given** 用户已登录，**When** 进入撰写新文章并立即发布，**Then** 文章对公众可见，且作者归属为当前用户；公开列表与详情均显示该作者用户名。
2. **Given** 用户 A 已发布文章，**When** 用户 B 登录后打开「我的文章」或尝试编辑 A 的文章，**Then** B 只能管理自己的稿件，无法修改或删除 A 的文章。
3. **Given** 访客未登录，**When** 打开已发布文章详情，**Then** 仍可完整阅读，无登录墙，且可见作者用户名。
4. **Given** 访客未登录，**When** 打开首页或公开文章列表，**Then** 每条已发布文章展示作者用户名。
5. **Given** 未登录访客，**When** 尝试进入撰写台或「我的文章」，**Then** 被引导至登录（或注册）后再继续。

---

### User Story 3 - 读者在正文下对文章点赞或点踩 (Priority: P1)

作为读者，我在文章详情页正文结束后、页脚之前看到点赞与点踩按钮及各自计数；我可以表态，并可取消或改选，计数随之更新。

**Why this priority**: 用户明确要求在框选位置交付表态能力；与注册可独立验收，但同属本规格交付范围。

**Independent Test**: 打开任意已发布详情页，在正文下方完成点赞/点踩/改选/取消，刷新后计数与本人表态状态仍正确。

**Acceptance Scenarios**:

1. **Given** 已发布文章详情页，**When** 页面加载完成，**Then** 在正文下方、页脚上方显示并排的点赞与点踩控件，并显示当前计数（无表态时为 0 或真实累计值）。
2. **Given** 已登录用户尚未对该文表态，**When** 点击点赞，**Then** 点赞计数加一，控件呈现已点赞态；点踩计数不变。
3. **Given** 已登录用户已点赞，**When** 再次点击点赞，**Then** 取消点赞，计数减一，控件恢复未表态态。
4. **Given** 已登录用户已点赞，**When** 点击点踩，**Then** 点赞取消且点踩生效（同一用户对同一文章同时只能保留一种表态），两侧计数同步正确。
5. **Given** 访客未登录，**When** 点击点赞或点踩，**Then** 不被记为有效表态，并被引导登录或注册（计数不因无效点击增加）。

---

### User Story 4 - 发现注册入口且不打断阅读 (Priority: P2)

作为访客，我能在合理位置发现注册/登录入口，但阅读已发布文章时不会被强制打断。

**Why this priority**: 开放注册需要可达性，但不得破坏既有沉浸阅读承诺。

**Independent Test**: 未登录浏览首页与详情，确认无登录墙；从导航或登录页可到达注册。

**Acceptance Scenarios**:

1. **Given** 访客在登录页，**When** 寻找注册，**Then** 有明确入口进入注册页。
2. **Given** 访客在阅读路径中，**When** 浏览列表与详情，**Then** 不被强制跳转注册/登录，入口不覆盖正文。

---

### Edge Cases

- 注册时用户名为空、格式不合法、密码少于 8 位或两次密码不一致（若提供确认框）：提示清晰，不创建账号。
- 并发注册同一用户名：仅一个成功，另一个得到占用提示。
- 不同用户保存文章时使用相同 slug：后保存方失败并得到占用提示，公开地址不串文。
- 用户对自己文章仍可点赞/点踩（允许），计数计入公开总数。
- 文章被删除或撤回为草稿后：公开详情不可见，表态入口不再对公众展示；历史表态不要求在公开侧继续展示。
- 网络失败时：表态操作给出可理解失败提示，界面计数不出现「假成功」。
- 快速连点：最终状态与计数一致，不出现重复累加。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供面向公众的账号注册能力，任何访客均可自助创建账号（废除「仅维护者预置作者账号、禁止自我注册」的既有限制，就本功能范围而言）。
- **FR-002**: 注册与登录表单 MUST 使用简体中文；账号标识 MUST 为全站唯一的**用户名**（非邮箱）；注册至少收集用户名与密码；密码 MUST 至少 **8** 个字符，该下限 MUST 在界面可见说明。
- **FR-003**: 注册成功后 MUST NOT 自动建立已登录会话；系统 MUST 引导用户至登录页，用户以该用户名与密码登录后，MUST 可使用既有撰写台相关能力（新建、编辑、草稿、发布、预约、撤回、删除等已交付能力），权限范围为**本人**文章。
- **FR-004**: 系统 MUST 保证用户只能管理自己的文章；MUST NOT 允许普通登录用户编辑或删除他人文章。
- **FR-004a**: 文章可读短标识（slug）MUST 在全站范围内唯一；任意两篇文章 MUST NOT 共用同一 slug；创建或修改时若冲突，MUST 明确提示用户更改。
- **FR-005**: 未登录访客 MUST 仍可阅读已发布文章列表与详情，MUST NOT 因本功能引入阅读登录墙。
- **FR-006**: 文章详情页 MUST 在正文内容下方、站点页脚上方展示点赞与点踩两个控件，并显示各自累计次数。
- **FR-007**: 同一登录用户对同一文章 MUST 最多保留一种有效表态（赞或踩）；重复点击同一控件 MUST 取消表态；切换另一控件 MUST 替换表态。
- **FR-008**: 未登录用户 MUST NOT 产生有效表态；尝试表态时 MUST 引导其登录或注册。
- **FR-009**: 表态计数 MUST 对所有访客可见（含未登录）；刷新页面后，本人表态状态与公开计数 MUST 保持一致。
- **FR-010**: 本功能 MUST NOT 引入关注、评论、转发、打赏等其它社交能力；MUST NOT 改变首页首屏阅读沉浸的既有定位。
- **FR-011**: 注册、登录、表态相关的用户可见文案与错误提示 MUST 使用简体中文。
- **FR-012**: 公开文章列表与文章详情 MUST 展示该文作者的用户名。

### Key Entities

- **用户账号**：可自助注册的登录主体；以全站唯一**用户名**为登录标识，并持有密码凭证；登录后可作为文章作者。
- **文章**：既有内容实体；新增与用户的归属关系（作者）；公开详情承载表态入口；slug 全站唯一。
- **文章表态**：某用户对某篇文章的赞或踩（互斥）；可取消；汇总为公开计数。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新访客可在 2 分钟内完成注册、再登录并进入可写作状态（正常网络下）。
- **SC-002**: 新注册用户首次发布文章后，未登录访客可在 1 分钟内于公开列表或详情看到该文。
- **SC-003**: 已登录用户在详情页完成点赞或点踩后，计数与选中态在 2 秒内反映到界面，刷新后仍然正确。
- **SC-004**: 抽测 10 组「用户 A 的文章 / 用户 B 登录」场景，B 无法改 A 的文章，通过率 100%。
- **SC-005**: 未登录阅读路径抽测（首页 + 至少 3 篇详情）无强制登录打断，通过率 100%。

## Assumptions

- 开放注册后，每位登录用户都是「可写作的作者」，不再区分单独的站点超管角色（超管/封禁等若需要，另开规格）。
- 登录标识为用户名，不强制邮箱、手机验证码或第三方 OAuth；既有种子账号需能继续以等价方式登录（实现阶段对齐迁移，不阻塞本规格）。
- 注册成功不自动登录，须回到登录页再登录一次。
- 密码最短 8 位；第一版不强制复杂度（大小写/数字/符号）规则。
- 表态必须登录，以避免开放注册后匿名刷票；计数对所有人可见。
- 点赞与点踩互斥，同一用户同一文章仅一种有效表态。
- 多作者并存时，公开列表展示所有人已发布文章，且列表与详情均显示作者用户名；「我的文章」仅显示当前用户稿件。
- 文章 slug 全站唯一（不按作者命名空间隔离）。
- 既有单作者种子账号可继续登录；其历史文章归属保持不变。
- 表态 UI 放在正文下方、页脚上方，风格对齐站点暗色/墨色体系与参照图的「图标 + 数字」并排按钮结构。
