# Feature Specification: 作者登录

**Feature Branch**: `002-author-login`

**Created**: 2026-07-30

**Status**: Draft

**Input**: User description: "添加一个登录页面（个人博客作者登录；与 001 边界衔接：读者阅读仍免登录）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 作者完成登录 (Priority: P1)

作为站点作者，我打开登录页，输入正确的账号与密码后，系统确认我已登录，并带我进入作者入口，以便后续使用仅作者可用的能力。

**Why this priority**: 没有可用的登录成功路径，本功能没有最小价值。

**Independent Test**: 使用预先配置好的作者凭证，仅打开登录页完成一次登录，即可验证成功态与进入作者入口；不依赖发文、评论或其他后台模块。

**Acceptance Scenarios**:

1. **Given** 作者未登录，**When** 访问登录页，**Then** 看到简体中文的登录表单（至少包含账号、密码与提交操作）。
2. **Given** 登录页已打开且凭证正确，**When** 作者提交登录，**Then** 登录成功，并进入作者入口页（或明确的已登录落地页）。
3. **Given** 作者刚登录成功，**When** 刷新浏览器或重新打开同一站点会话内的页面，**Then** 仍保持已登录状态（在会话有效期内）。

---

### User Story 2 - 错误凭证与反馈 (Priority: P1)

作为作者，当我输错账号或密码时，系统给出明确、可理解的失败提示，且不会误导为「已登录」。

**Why this priority**: 安全与可用性底线；与成功路径同等重要，可独立验收。

**Independent Test**: 在登录页故意提交错误凭证，仅验证失败提示与仍停留在未登录态。

**Acceptance Scenarios**:

1. **Given** 作者未登录，**When** 提交错误的账号或密码，**Then** 看到明确的失败提示（简体中文），且不进入作者入口。
2. **Given** 提交失败，**When** 作者再次查看页面，**Then** 可继续修改并重新提交，无需强制刷新整站才能重试。
3. **Given** 凭证错误，**When** 登录失败，**Then** 系统 MUST NOT 泄露「账号是否存在」以外的多余细节（对外提示保持笼统，例如「账号或密码不正确」）。

---

### User Story 3 - 登出 (Priority: P2)

作为已登录作者，我可以主动登出，之后再访问作者入口时需要重新登录。

**Why this priority**: 个人设备共用或结束操作时的基本安全需求；可在 P1 之后独立交付。

**Independent Test**: 先登录，再执行登出，随后尝试进入作者入口，验证被要求重新登录。

**Acceptance Scenarios**:

1. **Given** 作者已登录，**When** 选择登出，**Then** 会话结束，界面反映为未登录。
2. **Given** 作者已登出，**When** 直接访问作者入口页，**Then** 无法以已登录身份使用该入口，并被引导至登录页（或同等未授权提示后进入登录）。

---

### User Story 4 - 读者阅读不受登录打扰 (Priority: P1)

作为读者，我浏览文章列表与详情时，不需要登录，也不会被登录墙打断。

**Why this priority**: 与 001 核心阅读体验对齐；本功能不得破坏既有沉浸阅读承诺。

**Independent Test**: 在未登录浏览器中打开首页与任意已发布详情页，确认可完整阅读且无强制登录。

**Acceptance Scenarios**:

1. **Given** 访客未登录，**When** 打开首页文章列表，**Then** 可正常浏览，无登录强制弹窗或跳转。
2. **Given** 访客未登录，**When** 打开已发布文章详情，**Then** 可完整阅读正文，无登录墙。
3. **Given** 站点提供登录入口，**When** 读者在阅读路径中浏览，**Then** 登录入口不得喧宾夺主（不得覆盖正文或阻断首屏阅读）。

---

### Edge Cases

- 账号或密码留空提交时，应提示需填写，且不发起「假装成功」的跳转。
- 已登录作者再次访问登录页时，应直接进入作者入口，或明确提示已登录并提供前往入口/登出的路径（二选一，行为一致即可）。
- 会话过期后访问作者入口，应要求重新登录，并可用正确凭证再次进入。
- 连续多次错误尝试时，系统可降低滥用风险（例如短暂限制重试），但第一版至少保证失败提示清晰且不误登录；若做限制，须有可理解的中文说明。
- 网络或服务暂时不可用时，登录页应给出可理解的失败说明，而非空白或技术堆栈。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供独立的作者登录页，表单以简体中文呈现，至少支持账号与密码登录。
- **FR-002**: 系统 MUST 在凭证校验通过后建立作者已登录会话，并在会话有效期内跨页面保持该状态。
- **FR-003**: 系统 MUST 在凭证错误时拒绝登录，并向用户展示笼统、明确的失败提示（简体中文）。
- **FR-004**: 系统 MUST 提供登出能力，登出后作者入口不再以已登录身份可用。
- **FR-005**: 未登录访客 MUST 能继续使用 001 已交付的文章列表与详情阅读，MUST NOT 被要求登录才能阅读已发布内容。
- **FR-006**: 未登录用户访问作者入口（或其它本功能声明为「仅作者」的页面）时，MUST 被引导至登录页或收到等价的未授权处理后再进入登录。
- **FR-007**: 本功能 MUST NOT 提供面向公众的自我注册；作者账号由站点维护者预先配置。
- **FR-008**: 本功能 MUST NOT 交付完整内容管理后台、文章在线编辑器、评论管理或社交账号登录（这些若需要，另开规格）。
- **FR-009**: 登录成功后的落地 MUST 为极简「作者入口」页，至少可识别当前已登录身份，并提供登出入口；不要求在本功能内完成发文。
- **FR-010**: 登录相关用户可见文案与错误提示 MUST 使用简体中文。

### Key Entities

- **作者账号（Author Account）**: 预先配置的站点所有者凭证主体；本功能默认单一作者，不建模多租户或读者会员。
- **登录会话（Login Session）**: 表示作者已通过校验的有效时段；结束于登出或过期。
- **作者入口（Author Entry）**: 登录成功后的受保护落地页，证明「已登录」并作为后续作者能力的挂载点（本功能仅交付入口本身）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 持有正确凭证的作者可在 1 分钟内从打开登录页到确认已登录（含进入作者入口）。
- **SC-002**: 使用错误凭证登录时，100% 的尝试收到明确失败反馈，且不会进入作者入口。
- **SC-003**: 未登录读者打开首页与一篇已发布详情时，均可在不登录的情况下完成一次完整浏览/阅读，无强制登录打断。
- **SC-004**: 已登录作者执行登出后，再次访问作者入口时，在同一浏览器中必须重新登录才能进入。
- **SC-005**: 验收人员可仅凭本规格中的用户故事与验收场景完成走查，无需依赖未文档化的口头约定。

## Assumptions

- 本功能服务对象是站点作者（个人博客所有者），不是面向读者的会员体系。
- 作者账号预先存在（由维护者配置），第一版不提供注册、找回密码、邮箱验证或第三方登录。
- 与 `001-personal-blog` 的关系：001 中「第一版不做登录」被本规格显式扩展；**阅读路径免登录**的承诺继续有效，本规格不得引入阅读登录墙。
- 「作者入口」在本功能中保持极简，不包含 Markdown 发文流程的替代实现；仓库 Markdown 发布仍可按 001 方式工作。
- 第一版默认单一作者账号即可满足需求。
- 登录页可通过已知地址访问；是否在站点页头放置低调入口由实现阶段决定，但不得破坏阅读沉浸感。
- 会话有效期采用常见个人站点惯例（例如数小时至数天量级），具体数值在方案阶段确定；规格只要求「有效期内保持、过期需重登」。
