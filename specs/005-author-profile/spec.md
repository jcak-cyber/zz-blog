# Feature Specification: 个人中心资料（昵称 / 头像 / 简介）

**Feature Branch**: `005-author-profile`

**Created**: 2026-08-14

**Status**: Draft

**Input**: User description: "个人中心新增昵称修改、头像上传、个人简介，如图"

**UI 参照**：登录后「手稿台 / 个人中心」双栏布局——左侧展示昵称与「修改昵称」入口；右侧提供圆形头像上传区、「当前账号」信息、既有写作入口，以及「个人简介」多行编辑区（空态占位文案示意：「这个人很懒，什么都没有留下…」）。视觉须延续 zz-blog 墨色手稿气质，与现有手稿台卡片风格一致。

## Clarifications

### Session 2026-08-14

- Q: 用户从未设置昵称，或想清空昵称时，系统应如何处理？ → A: 昵称必填：注册/首次进入时默认等于用户名，之后只能改成其他合法昵称，不能清空
- Q: 个人简介应如何触发保存？ → A: 显式保存：简介旁提供保存按钮，点击后才写入并提示成功/失败
- Q: 用户上传头像后，是否允许删除头像并恢复为无图占位？ → A: 可删除：删除后恢复占位样式，个人中心无头像

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 修改并展示昵称 (Priority: P1)

作为已登录用户，我在个人中心（手稿台）看到当前昵称，并能修改它；修改后立即在个人中心可见。登录用的用户名保持不变，仍显示在「当前账号」处。

**Why this priority**: 昵称是个人中心最基础的身份展示与编辑能力，也是图示中明确标注的能力。

**Independent Test**: 登录后打开个人中心，修改昵称并保存，刷新后昵称仍为新值；「当前账号」仍为原用户名。

**Acceptance Scenarios**:

1. **Given** 用户已登录并打开个人中心，**When** 查看左侧手稿台区域，**Then** 看到当前昵称（新用户或既有账号首次启用本功能时，昵称默认等于登录用户名），以及「修改昵称」入口。
2. **Given** 用户点击「修改昵称」，**When** 输入合法新昵称并确认，**Then** 个人中心立即展示新昵称，并给出成功反馈（或等价确认）。
3. **Given** 用户提交空昵称、超长昵称或含不允许字符的昵称，**When** 尝试保存，**Then** 看到简体中文错误提示，原昵称不被错误覆盖（空昵称一律拒绝）。
4. **Given** 用户已修改昵称，**When** 查看「当前账号」一行，**Then** 仍显示登录用户名（及角色，若页面已有），不因改昵称而改变。

---

### User Story 2 - 上传或更换头像 (Priority: P1)

作为已登录用户，我可以在个人中心上传或更换头像；上传成功后圆形头像区展示新图片。

**Why this priority**: 图示右侧明确要求头像上传入口，是个人中心可识别性的核心视觉要素。

**Independent Test**: 选择一张合规图片上传，个人中心头像区变为该图；刷新后仍保持。

**Acceptance Scenarios**:

1. **Given** 用户已登录打开个人中心，**When** 查看右侧头像区，**Then** 看到可点击的上传/更换头像入口（无头像时为占位样式）。
2. **Given** 用户选择合规图片（如常见图片格式、体积在约定上限内），**When** 完成上传，**Then** 头像区展示新头像，并给出成功或完成态反馈。
3. **Given** 用户选择不支持的文件类型或过大文件，**When** 尝试上传，**Then** 看到明确失败提示，原头像（若有）保持不变。
4. **Given** 用户已上传头像，**When** 再次上传另一张合规图片，**Then** 头像更新为最新一张。
5. **Given** 用户已有头像，**When** 选择删除头像并确认成功，**Then** 头像区恢复为无图占位样式；刷新后仍无头像。
6. **Given** 用户当前无头像，**When** 查看头像区，**Then** 不展示「删除头像」或该操作不可用。

---

### User Story 3 - 编辑个人简介 (Priority: P1)

作为已登录用户，我可以在个人中心编辑并保存个人简介；空简介时看到友好占位提示。

**Why this priority**: 图示明确包含「个人简介」编辑区，与昵称、头像共同构成资料完整性。

**Independent Test**: 填写简介并保存，刷新后内容仍在；清空后恢复空态占位。

**Acceptance Scenarios**:

1. **Given** 用户打开个人中心且尚无简介，**When** 查看简介区域，**Then** 看到可编辑区域及空态占位提示（语义等价于「尚未填写简介」类文案）。
2. **Given** 用户输入简介内容并点击「保存简介」（或等价显式保存控件），**When** 操作成功，**Then** 内容被保留，刷新后仍可见，并看到成功反馈。
3. **Given** 用户仅修改简介文本但未点击保存，**When** 离开个人中心或刷新页面，**Then** 未保存的修改不生效（仍为上次已保存内容或空态）。
4. **Given** 用户输入超过允许长度的简介，**When** 尝试保存，**Then** 看到长度限制提示，不保存超限内容。
5. **Given** 用户将简介清空并点击保存，**When** 再次查看，**Then** 恢复空态占位，不显示乱码或残留错误内容。

---

### User Story 4 - 资料编辑不打断既有写作入口 (Priority: P2)

作为已登录用户，我在完善资料的同时仍能使用「我的文章」「写新文章」「登出」「返回阅读」等既有入口，个人中心布局不遮挡这些核心操作。

**Why this priority**: 个人中心首先是作者工作台入口；资料能力不得挤掉写作路径。

**Independent Test**: 在已展示昵称/头像/简介的个人中心，仍可一键进入我的文章、写新文章、返回首页阅读。

**Acceptance Scenarios**:

1. **Given** 用户在个人中心，**When** 点击「我的文章」或「写新文章」，**Then** 进入对应既有流程，行为与改版前一致。
2. **Given** 用户在个人中心，**When** 点击「返回阅读」，**Then** 回到公开阅读首页；登录态保持。
3. **Given** 未登录访客，**When** 尝试打开个人中心，**Then** 被引导登录，无法编辑他人或匿名资料。

---

### Edge Cases

- 昵称与其他用户重复：允许（昵称非登录标识）；登录唯一性仍由用户名保证。
- 尝试将昵称清空：拒绝保存，保留原昵称并提示。
- 网络失败或上传中断：给出可理解失败提示；界面不出现「假成功」头像或简介。
- 快速连点保存/上传：最终展示与服务器一致的最新成功结果，不产生错乱状态。
- 仅登录本人可改本人资料；不得通过猜测地址修改他人昵称、头像或简介。
- 头像文件损坏或无法解码：提示失败，不展示破图作为成功态。
- 删除头像失败（网络等）：保留原头像并提示，不出现「已删除」假象。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在已登录用户的个人中心（手稿台入口页）提供昵称展示与修改能力。
- **FR-002**: 昵称 MUST 与登录用户名分离；修改昵称 MUST NOT 改变登录用户名或登录方式。
- **FR-003**: 昵称 MUST 始终非空：注册成功或既有账号首次具备资料能力时，昵称 MUST 默认等于该用户的登录用户名；之后仅可修改为其他合法昵称，MUST NOT 允许清空。
- **FR-003a**: 昵称 MUST 有明确长度与字符约束（合理默认：约 2–32 个可见字符，允许中文），非法输入 MUST 以简体中文提示拒绝。
- **FR-004**: 系统 MUST 提供头像上传/更换能力；成功后个人中心 MUST 展示当前头像。
- **FR-004a**: 系统 MUST 允许用户删除已上传的头像；删除成功后个人中心 MUST 恢复无图占位；无头像时 MUST NOT 提供有效的删除操作（隐藏或禁用）。
- **FR-005**: 头像上传 MUST 校验类型与大小（合理默认：常见图片格式；单文件体积上限对用户可见说明）；不合规 MUST 拒绝并提示。
- **FR-006**: 系统 MUST 提供个人简介的查看与编辑能力；空简介 MUST 显示友好占位文案；简介 MUST 通过显式「保存」操作写入，MUST NOT 仅因失焦或离开页面而自动保存。
- **FR-006a**: 显式保存成功或失败时，系统 MUST 给出可感知的简体中文反馈；未点击保存前的编辑 MUST NOT 被持久化。
- **FR-007**: 个人简介 MUST 有最大长度限制（合理默认：数百字量级，具体上限在实现方案中落数值但对用户可见或可感知），超限 MUST 拒绝保存。
- **FR-008**: 昵称、头像、简介的读取与更新 MUST 仅限本人已登录会话；未登录 MUST NOT 编辑。
- **FR-009**: 个人中心 MUST 保留既有「我的文章」「写新文章」「登出」「返回阅读」等入口，资料区不得遮挡或移除这些能力。
- **FR-010**: 本功能相关用户可见文案与错误提示 MUST 使用简体中文。
- **FR-011**: 本功能 MUST NOT 引入公开「作者主页」社交聚合、关注、私信等能力；MUST NOT 改变公开阅读路径的免登录可读承诺。
- **FR-012**: 公开文章列表/详情中的作者展示 MUST 显示该作者的昵称（因昵称必填且有默认值，无需再回退到「未设置」态）。

### Key Entities

- **用户资料（Profile）**：隶属于已注册用户；关键属性包括登录用户名（不可因本功能变更）、昵称、头像、个人简介、角色等。
- **头像资源**：用户上传的个人形象图片；与用户资料一对一（当前生效一张）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已登录用户可在约 1 分钟内完成「打开个人中心 → 修改昵称并确认」全流程。
- **SC-002**: 已登录用户可在约 2 分钟内完成一次合规头像上传，并在个人中心立即看到新头像；亦可在约 1 分钟内删除头像并看到占位恢复。
- **SC-003**: 已登录用户可在约 1 分钟内完成简介编辑并确认保存；刷新后内容不丢失。
- **SC-004**: 未登录用户无法修改任何用户的昵称、头像或简介（尝试时被引导登录或失败）。
- **SC-005**: 资料相关失败（非法昵称、超限简介、不合规图片、网络错误）均有可读的简体中文提示，且不出现错误的「已保存/已上传」假象。

## Assumptions

- 个人中心即现有登录后「手稿台 / AUTHOR ENTRY」入口页，在此页扩展资料能力，不另开无关的新站点分区。
- 登录标识仍为用户名；昵称仅用于展示（个人中心 + 公开文章作者名位置），不用于登录；昵称必填，默认等于用户名且不可清空。
- 头像与简介以个人中心管理为主；不单独建设公开作者主页。公开列表/详情展示作者昵称，不强制展示头像与简介。
- 头像支持上传、更换与删除；删除后回到占位态。类型/大小与现有上传策略对齐或略收紧，具体数值在方案阶段确定并对用户可见。
- 简介默认空态占位可采用图示语义文案或等价友好提示；简介 MUST 使用显式保存按钮写入，不采用失焦自动保存。
- 不在本功能中改密码、改用户名、绑定邮箱/手机或做实名认证。
- 既有账号在启用本功能时若尚无昵称字段值，MUST 回填为当前用户名。
