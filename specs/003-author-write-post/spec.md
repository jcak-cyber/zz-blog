# Feature Specification: 作者撰写文章

**Feature Branch**: `003-author-write-post`

**Created**: 2026-07-30

**Status**: Draft

**Input**: User description: "添加作者的编写博客文章的页面，大概结构如图，样式风格用本项目的来"

**UI 参照**：布局结构参照 `docs/ui/003-author-write-post-layout.png`（三栏：信息侧栏 / 正文编辑 / 预览与发布）；**视觉风格必须沿用 zz-blog 现有墨色手稿气质**（森绿、暖赭、纸感），不得照搬参照图中的浅色后台 / 青绿组件库外观。

## Clarifications

### Session 2026-07-30

- Q: 作者要打开已有草稿或已发布文章继续编辑时，第一版应如何找到并进入它们？ → A: 作者区提供「我的文章」列表（含草稿与已发布），点击进入编辑；另有新建入口
- Q: 第一版是否允许作者删除已经发布的文章（不只是删草稿）？ → A: 可删已发布文章，须确认；删后公开侧立即不可见
- Q: 新建文章时，可读短标识（网址里的那一段）应如何产生？ → A: 按标题自动生成建议 slug，作者可改；已发布后默认锁定（改则明确警告）
- Q: 参照图里有「定时发布时间」选择，第一版要不要支持预约发布？ → A: 支持指定未来时间自动变为公开
- Q: 文章已经公开后，第一版要不要支持「撤回为草稿」？ → A: 支持撤回为草稿（须确认）；公开侧立即不可见，稿件保留

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登录后撰写并发布新文章 (Priority: P1)

作为已登录作者，我打开撰写页，填写标题与正文，保存为草稿或直接发布后，读者可在公开站点看到已发布文章。

**Why this priority**: 没有「能写并发布」就没有本功能的最小价值。

**Independent Test**: 使用已登录作者会话，仅打开撰写页完成一篇新文的填写与发布，在未登录浏览器打开首页/详情即可验证公开可见。

**Acceptance Scenarios**:

1. **Given** 作者已登录，**When** 进入撰写新文章页，**Then** 看到与参照图同构的编辑布局（左侧文章信息区、中部正文编辑区、右侧预览/发布区或等价信息架构），文案为简体中文，视觉为站点既有风格。
2. **Given** 撰写页已打开，**When** 作者填写标题与正文并选择立即发布，**Then** 文章以已发布状态出现在公开列表，且可用稳定可读地址打开详情。
3. **Given** 作者选择未来的定时发布时间并确认预约，**When** 当前时间尚未到达该时刻，**Then** 文章不对公众可见；到达（或超过）该时刻后，公开列表与详情可见。
4. **Given** 文章已对公众可见，**When** 未登录读者打开首页，**Then** 可见该文（含标题；若有封面/摘要则按现有列表规则展示）。
5. **Given** 作者未登录，**When** 直接访问撰写页或「我的文章」，**Then** 无法编辑或查看该列表，并被引导至登录（或等价未授权处理）。

---

### User Story 2 - 保存草稿并稍后继续 (Priority: P1)

作为作者，我可以保存尚未公开的草稿，稍后从「我的文章」列表回来继续编辑，读者看不到草稿。

**Why this priority**: 写作过程需要中断与恢复，与发布同等重要。

**Independent Test**: 保存一篇草稿后，在未登录浏览器确认公开列表与详情不可见；再以作者身份在「我的文章」中打开该草稿继续编辑。

**Acceptance Scenarios**:

1. **Given** 撰写页有标题或正文内容，**When** 作者保存草稿，**Then** 系统确认已保存，草稿不对公众列表可见。
2. **Given** 存在已保存草稿，**When** 作者在「我的文章」列表中打开该草稿，**Then** 可恢复此前填写的标题、正文及已填元信息并继续编辑。
3. **Given** 草稿存在，**When** 未登录访客浏览公开站点，**Then** 看不到该草稿条目，也无法通过猜测地址阅读其正文。
4. **Given** 作者已登录，**When** 打开「我的文章」列表，**Then** 可见自己的草稿、预约中与已发布文章入口，并可进入对应编辑页；同时具备「新建文章」入口。
5. **Given** 列表中有已发布文章，**When** 作者点击进入编辑并保存，**Then** 可更新该文内容（公开侧随后反映已发布内容的变更）。
6. **Given** 列表中有预约中文章，**When** 作者打开编辑并取消预约或改回草稿，**Then** 文章在预约生效前保持不对公众可见。

---

### User Story 3 - 编辑元信息、封面与摘要 (Priority: P2)

作为作者，我可以在侧栏维护分类/标签（若站点已支持）、封面与摘要，并在预览区看到列表卡片的大致效果。

**Why this priority**: 提升发布完成度；可在 P1 主路径之后独立交付。

**Independent Test**: 为一篇文章设置摘要与可选封面后发布，在公开列表核对展示；标签/分类按站点既有能力展示。

**Acceptance Scenarios**:

1. **Given** 撰写页，**When** 作者填写摘要并（可选）设置封面，**When** 发布成功，**Then** 公开列表/详情按既有规则展示摘要与封面。
2. **Given** 作者添加标签（及站点已启用的分类），**When** 发布或保存，**Then** 这些元信息与文章一并保存，并在详情或列表中按既有规则可见。
3. **Given** 元信息变更，**When** 查看撰写页预览区，**Then** 预览反映当前标题/摘要/封面等关键信息（不必与线上像素级一致）。

---

### User Story 4 - 预览、字数与删除草稿 (Priority: P2)

作为作者，我需要看到正文预览与字数，并能删除不再需要的草稿。

**Why this priority**: 降低误发与残留草稿；依赖草稿能力，故次于 US2。

**Independent Test**: 在编辑中查看预览与字数；删除一篇草稿后确认其不可再打开且仍不对公众可见。

**Acceptance Scenarios**:

1. **Given** 正文有内容，**When** 作者查看预览，**Then** 能看到基于当前正文的可读预览（Markdown 渲染效果即可）。
2. **Given** 正文有内容，**When** 查看字数统计，**Then** 显示可理解的字数信息（至少含正文规模量级）。
3. **Given** 存在草稿，**When** 作者确认删除草稿，**Then** 草稿被移除，作者无法再打开该草稿进行编辑。
4. **Given** 存在已发布文章，**When** 作者确认删除该文，**Then** 文章从作者列表与公开列表/详情中立即消失，读者无法再阅读。
5. **Given** 存在已发布文章，**When** 作者确认撤回为草稿，**Then** 公开侧立即不可见，作者仍可在「我的文章」中打开该草稿继续编辑。

---

### Edge Cases

- 标题为空或正文为空时尝试发布：阻止发布并给出明确中文提示。
- 可读地址（短标识）冲突：阻止保存/发布并提示需更换，不得覆盖他人文章。
- 已发布文章的短标识默认锁定；作者若强行修改须先看到「旧链接将失效」类明确警告。
- 仅改标题不改短标识：已发布文章的公开地址保持稳定（与 001 约定一致）。
- 上传封面失败或格式不支持：提示失败原因，不影响已填写的文字内容。
- 编辑过程中会话过期：保存/发布失败时提示需重新登录，已输入内容尽可能不静默丢失（至少给出明确失败说明）。
- 网络或服务不可用：保存/发布给出可理解失败提示，而非空白页。
- 删除已发布文章：未确认前不得删除；确认后公开侧立即不可访问该文。
- 撤回已发布为草稿：未确认前不得撤回；确认后公开侧立即不可见，稿件仍可编辑。
- 预约发布时间早于或等于「现在」：按立即发布处理，或提示作者改选未来时间（行为须一致且有中文说明）。
- 预约尚未生效时作者取消预约：文章保持非公开（草稿或等价），公众不可见。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 为已登录作者提供「撰写 / 编辑文章」页面及「我的文章」列表（含草稿与已发布）；未登录 MUST NOT 可写入或查看该列表。列表 MUST 提供进入编辑与新建文章的入口。
- **FR-002**: 撰写页信息架构 MUST 覆盖参照图的核心分区：文章信息（标题等）、正文编辑、预览与发布操作；桌面宽屏宜呈多栏，窄屏可折叠为上下堆叠，但能力不减少。
- **FR-003**: 正文编辑 MUST 以 Markdown 为作者输入格式（可提供常用格式插入辅助），与宪章「Markdown 主工作流」一致；MUST NOT 以复杂富文本 CMS 为默认。
- **FR-004**: 作者 MUST 能将文章存为草稿、立即发布为公开文章，或预约在未来某一时刻自动变为公开；草稿与「未到点的预约稿」MUST NOT 出现在公开列表或可公开阅读的详情中。
- **FR-015**: 作者 MUST 能为预约稿指定发布时间；在到达该时间之前 MUST 能取消预约或改回草稿/改为立即发布；到达或超过该时间后，文章 MUST 按已发布规则对公众可见。「我的文章」列表 MUST 能区分草稿、预约中、已发布等状态。
- **FR-005**: 新建时系统 MUST 可根据标题自动生成可读短标识（slug）建议值，且作者 MUST 能在发布前修改；公开网址基于该标识。已发布后短标识默认锁定；若允许修改 MUST 先给出会影响旧链接的明确警告。改标题 MUST NOT 自动改掉已锁定的短标识。
- **FR-006**: 作者 MUST 能编辑可选摘要与可选封面；封面支持上传或填写可用图片地址（与站点既有媒体能力对齐）。
- **FR-007**: 作者 MUST 能维护标签；分类若站点数据模型已支持则可编辑，否则本功能可不强造分类 UI。
- **FR-008**: 系统 MUST 提供基于当前内容的预览与字数反馈，以及保存状态的可见提示（如「已保存」/失败原因）。
- **FR-009**: 作者 MUST 能删除草稿与已发布文章；删除已发布文章 MUST 有确认步骤，且删除后公开列表与详情立即不可见。
- **FR-016**: 作者 MUST 能将已发布文章撤回为草稿（须确认）；撤回后公开侧立即不可见，稿件保留在「我的文章」中可继续编辑；撤回 MUST NOT 等同于删除。
- **FR-010**: 页面视觉 MUST 使用本站既有设计语言（墨色手稿：纸感、森绿/暖赭、既有字体与动效气质）；MUST NOT 复制参照图的浅色通用后台皮肤作为默认视觉。
- **FR-011**: 本功能 MUST 与既有仓库 Markdown 导入工作流共存：不强制废除 `content/posts` 导入；Web 撰写与导入写入同一套「文章」真相来源即可。
- **FR-012**: 本功能 MUST NOT 交付读者评论开关的真实生效、点赞、多人协作或复杂权限矩阵（参照图中的评论/点赞仅作布局参考，产品上不启用）。
- **FR-013**: 用户可见文案与错误提示 MUST 使用简体中文。
- **FR-014**: 「我的文章」列表 MUST 区分草稿、预约中与已发布状态展示，便于作者识别并继续编辑。
### Key Entities

- **文章稿件（Post Draft/Published）**: 含标题、短标识（可自标题建议生成）、正文（Markdown）、摘要、封面、发布状态（草稿 / 预约中 / 已发布）、计划发布时间（可选）、实际发布时间、标签（及可选分类）；支持撤回为草稿与删除；与 001/002 中的文章实体为同一概念的写作侧操作。
- **撰写会话（Editor Session）**: 作者在编辑器中的当前编辑状态（含未保存变更提示）；依赖 002 登录会话。
- **封面媒体（Cover Media）**: 可选；关联到文章的展示图。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 已登录作者可在 5 分钟内完成「打开撰写页 → 填写标题与一段正文 → 立即发布 → 在公开首页看到该文」。
- **SC-008**: 设置未来预约发布时间的文章，在预约时刻之前未登录访问公开首页出现次数为 0；预约时刻到达后，未登录读者可在公开首页看到该文。
- **SC-002**: 保存为草稿的文章在未登录访问公开首页时出现次数为 0；直接访问其详情亦不可读正文。
- **SC-003**: 在标准笔记本宽度下，撰写页首屏可同时辨认「信息区、编辑区、发布/预览操作」三大区域（或窄屏下通过清晰分区标题等价达到）。
- **SC-004**: 90% 的试写走查中，作者首次即可完成保存草稿或发布，无需查阅未文档化口头说明。
- **SC-005**: 视觉走查中，撰写页与公开阅读页同属一套品牌气质（墨色手稿），不会被误认为另一套浅色后台产品。
- **SC-007**: 作者确认删除一篇已发布文章后，未登录访问其原公开地址时无法阅读正文（表现为未找到或等价不可用）。
- **SC-009**: 作者确认将已发布文章撤回为草稿后，未登录访问公开首页与原详情地址均不可读该文；作者仍可在「我的文章」中打开该草稿。

## Assumptions

- 作者身份与登录能力已由 `002-author-login` 提供；本功能挂在登录后的作者区域：含「我的文章」列表、新建与编辑页。
- 正文以 Markdown 为主，预览为渲染后的阅读样式；不把「所见即所得富文本」作为第一版必达。
- 参照图用于**布局与信息架构**，不用于视觉皮肤；评论开关、点赞数等社交控件第一版不做。
- 仓库 Markdown 导入与 Web 撰写长期共存；冲突文章以短标识唯一性约束处理。
- 单一作者站点；不建模多作者同时编辑同一篇。
- 新建时可按标题生成 slug 建议；发布前可改；已发布后默认锁定（改则警告）。
- 支持立即发布与定时预约发布；预约未生效前不对公众可见，生效后按已发布处理；预约可取消或改回草稿。
- 支持将已发布文章撤回为草稿（须确认）；与删除不同，撤回保留稿件。
- 删除草稿与删除已发布文章均在第一版支持；删除已发布须确认，公开侧立即不可见。
- 自动保存可以有，但第一版至少保证显式「保存草稿」可靠；自动保存间隔不作为验收硬指标。
- 定时生效以站点服务器时间为准；界面须让作者理解所选时间含义（避免 silently 用错时区）。
